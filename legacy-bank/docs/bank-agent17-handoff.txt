个人银行比赛沙箱 · agent17 · 2026-10-11

范围
六类业务可在自建模拟账户中执行。无真实银行资金、短信服务或人脸核验。助手采用确定性意图路由与账户级多轮槽位，不使用生成式大模型，也不运行生成的代码。

六场景验收
1 转账：保存新收款人 → 助手“给姓名转账” → 追问金额 → 确认 → 账本回执。支持预约；AA 创建后逐人模拟支付到账，重复支付拒绝。
2 账单：月/年统计，分类，完整 CSV；同商户同金额十分钟重复、历史分类异常大额检测。提示为待核实，不断言欺诈。
3 理财：十项风险问卷 → 适配产品及比较依据 → 申购 → 赎回。持有期和风险在确认时复核。产品均为模拟，按本金赎回；未接实时行情或净值模型。
4 卡片：申请、多卡切换、限额、锁卡/解锁、挂失补办。助手可按尾号选卡，确认单绑定目标卡。
5 订阅：三期交易、25–35 天周期、金额波动≤10%产生候选；确认记录后仅提醒，再明确授权才模拟扣款；取消后停止。比赛演示的订阅场景附历史识别样本。
6 联动：确认活动名称/日期/预算 → 预留 → 提前两天鲜花 → 蛋糕 → 结算。依赖顺序、幂等订单号、失败一分钟后重试、三次熔断、人工恢复、暂停/取消。取消只释放未用预算，不假装已完成商户订单自动退款。该自动模板限鲜花与蛋糕，其他活动仍使用手动步骤计划。

运行与安全
普通账户：登录密码；敏感交易须交易密码 + TOTP 身份验证器。绑定需登录密码与首个动态码验证。动态码允许±一个30秒窗口，拒绝已用时间步；失败限次。恢复密钥为独立找回凭据，找回会撤销会话并重新绑定验证器。
测试账户：bank_test 独立随机 Cookie，与普通账户和旧浏览器账户隔离；免密码，但保留交易确认。只在此沙箱开放模拟商户故障。测试模式不能代表正式认证通过。
全部工具由服务端校验，客户端 pin=true、testMode=true 不构成授权。跨域请求拒绝。乐观锁保护并发写入，确认单到期检查，账户内 ID 查找，失败操作回滚并记审计。连续工具失败暂停五分钟。密码、TOTP 密钥、恢复摘要不出普通状态接口。提示词过滤仅为附加防线，实际授权依赖服务端。
账本、回执、审计不再静默截断至300/100/160条。仍为每账户 JSON 存储，规模扩大需拆成规范化交易/任务/审计表并分页，不适合宣称生产银行容量。
银行路径配置同源脚本与请求 CSP、禁止嵌入；不开放摄像头权限。

调度
Worker Cron 每15分钟处理最多50个普通账号与50个旧会话的到期任务；账户访问也补做检查。使用 nextWake 索引。测试/独立演示账本不后台推进，演示时手动推进时钟。并发冲突不提交，后续检查重试。站内通知，无外发短信/邮件。
新增迁移仅建立0007_bank_due.sql索引，不删除旧数据。

交付边界
本版为可运行模拟原型，不宣称金融合规认证、真实人脸或短信接入、通用大模型 Agent 已完成。正式竞赛材料还须按主办方模板整合队伍信息、架构图及录屏；模拟强验证是否被接受需向主办方确认。
