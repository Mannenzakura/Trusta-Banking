Business32 — 2026-10-11 — 业务闭环检查与补齐

本轮目标：让已实现业务的结果可追溯、可后续管理，补全异常记录和部分操作；不以增加页面入口代替业务实现。

账户与卡片
- 保留每卡余额、预留、可用金额与Ⅰ/Ⅱ类额度校验。
- 新增本卡流水入口、按卡查询办理记录；信用卡月账单可展开消费、已偿还及待还分配。
- 锁卡、挂失、补卡、限额与卡面定制沿用原服务端验证。

转账与账单
- 确认时固定收款信息快照，修改或停用联系人不会悄悄改变已确认预约。
- 收款人支持停用、恢复；新转账不能使用停用联系人，旧记录保留。
- 明示费用与记账时点；即时转账、卡间转账、预约执行关联准确交易编号。
- 办理记录可按关键词、状态和银行卡筛选，展开确认内容、执行进度和相关入账，下载原回执。
- 旧数据没有关联编号时不按金额或时间猜测关联。

信用卡
- 消费、额度、账单、还款既有流程保留。
- 每期账单下可看逐笔消费及还款抵扣结果；还款操作关联真实扣款借记卡的流水。
- 暂不实现利息、最低还款、分期、取现和真实授信，界面仍明确这些边界。

理财与黄金
- 新增部分本金赎回及全部赎回，展示返还原卡、剩余持仓。
- 确认时重新校验持有期、原卡状态、报价时持仓是否变更。
- 黄金部分赎回按整数微克分摊，末笔带走舍入余数，保持金额与克数守恒。
- 市场行情仍仅作参考；测试成交价、原本金赎回不冒充真实净值成交。

订阅与生活权益
- 更换扣款卡经过确认与既有强验证；不恢复已取消的授权、不立即扣款。
- 每次周期扣款成功或失败独立留档；失败无新扣款、本期不自动补扣。
- 权益领取及使用有持久结果记录，禁止重复领取、重复核销、过期使用。
- 服务结果接入站内通知。

联动计划
- 原有步骤依赖、预算预留、失败重试、暂停/恢复/取消保持。
- 创建回执显示待执行；状态跟随计划更新，不再把保存自动计划称作全部完成。
- 自动订单、预约转账的实际扣款关联原确认回执。

安全及数据边界
- 业务失败在 API 回滚之后单独记录，不保存请求体、密码或动态码。
- 原有同源检查、账户隔离、服务端权限校验、交易密码/TOTP、乐观锁与确认幂等保留。
- 保留测试模式。全部资金与商户仍为测试环境，不新增真实银行、短信、人脸或真实兑付连接。
- 多年大规模账本分页、规范化交易表、运维告警与灾备、正式金融产品协议、真实支付结算等仍需独立设计和后端接入，不能认定生产银行系统已完善。

验证
- 81 项 node 测试通过，包含新增 12 项业务与 API 回滚/隐私测试。
- 浏览器实测转账→确认→结果→关联入账；部分赎回；代扣卡变更；收款人停用/恢复；记录搜索及展开。
- 390px 手机宽度检查首页、财富、生活、个人中心和记录详情，无横向溢出；浏览器未报告脚本错误。
- 未使用真实银行卡、真实支付或个人敏感资料进行测试。
